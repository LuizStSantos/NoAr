# Actual NoAr integration smoke test

`integrated_smoke.py` tests the compiled NoAr application and its authenticated
HTTP API, scheduler, native media engine and recording output. It is separate
from the standalone Python prototype operated by `run.sh`.

Use a disposable development machine. Do not point this test at an on-air
installation. It creates its own database, account, storage and playlists under
ignored `qa/gstreamer/artifacts/integrated-*`. Credentials are generated in
memory and are not printed. It refuses a configured NoAr installation or an
already active MediaMTX SRT session.

## Prerequisites

- A compiled NoAr binary from this branch and the native dependencies described
  in `docs/developer.md`. This harness uses the API. The debug binary does not
  serve the Vue UI; browser tests need a separate frontend server or a release
  binary under the existing build architecture.
- Python 3.9 or newer, FFmpeg and FFprobe on the host PATH.
- Synthetic `qa/gstreamer/fixtures/a.mp4` and `b.mp4` generated by the prototype
  fixture service. Build its tools with `./run.sh build`, then run
  `docker compose --project-name noar-gstreamer-prototype --file compose.yaml run --rm --no-deps fixtures`
  from `qa/gstreamer` if the files do not already exist.
- Free loopback ports: HTTP 19787, SRT/UDP 29890 and MediaMTX API/TCP 29997.

From the repository root, compile the application:

```sh
npm ci
npm run build
cargo build --no-default-features --features embed_frontend
```

Start only the dedicated MediaMTX test container:

```sh
docker run --detach --rm --name noar-gstreamer-integrated-mediamtx \
  --publish 127.0.0.1:29890:8890/udp \
  --publish 127.0.0.1:29997:9997/tcp \
  --mount "type=bind,src=$PWD/qa/gstreamer/mediamtx.yml,dst=/mediamtx.yml,readonly" \
  bluenviron/mediamtx:1.15.3
```

## Run and inspect

```sh
NOAR_GST_STAGING=1 NOAR_GST_BINARY="$PWD/target/debug/noar" \
  python3 qa/gstreamer/integrated_smoke.py

NOAR_GST_STAGING=1 NOAR_GST_BINARY="$PWD/target/debug/noar" \
  NOAR_GST_TEST_RECOVERY=1 python3 qa/gstreamer/integrated_smoke.py
```

Each run lasts approximately 60 seconds plus setup and capture analysis. The
test triggers three eight-second live events, with Clock, Continue and Clock
return policies. Recovery mode stops the synthetic publisher for four seconds
during the first live event and verifies subsequent live admissions. The NoAr
process, input publisher and receiver stop in a `finally` block. The dedicated
MediaMTX container remains available for another run.

The script writes `report.json`, packet capture, timestamped receiver progress,
API status snapshots and process logs to a new artifact directory. It reports `FAIL` and
exits nonzero if any smoke gate fails. It checks actual decoded A/B/live
markers, all three live entries, independent receiver progress (maximum 750 ms
between observed advances), captured duration, packet timestamp continuity,
A/V ending alignment, persistent output sessions, reported SRT drops and
recording file presence. The receiver warm-up before its first progress report
is excluded; duration and transition gates still apply. The terminal interval
after the last progress update is included so a stall at the end cannot pass
merely because no later progress sample arrived.

Recording presence does not prove recording decode or retention. This test
does not exercise browser clicks, automatic wall-time admission, HLS, RTMP,
SCTE-35, GPU playback or a long soak. A smoke PASS is not a release approval.
See `docs/gstreamer-integration.md` for the current integration status.

Stop only the dedicated test MediaMTX when finished:

```sh
docker stop noar-gstreamer-integrated-mediamtx
```

Keep evidence until reviewed. Artifacts may contain disposable session and
configuration data; do not commit them. No production Compose project or data
directory is used by these commands.
